# 排障指南

> 覆盖常见故障的诊断顺序、判断依据与处置方法。
> 组件职责见 [核心组件](components.md)；配置项见 [配置手册](configuration.md)。

## 1. 诊断顺序

遇到"数据没有 / 任务不动 / 查询结果不对"时，按以下顺序排查，
绝大多数问题在前两步定位：

1. **进程健康**：启动日志与退出码——配置非法（退出码 2）与就绪检查失败（退出码 1）
   会在启动时直接暴露；容器场景 `docker compose ps` 看健康状态；
2. **任务运行记录**：`GET /v1/jobs`（状态、窗口、耗时、错误）与
   `GET /v1/watermarks`（增量水位）；WebUI 任务页同源；
3. **数据源侧**：凭证是否注入、限流是否超时、源端是否已发布当日数据；
4. **存储侧**：迁移版本、schema 是否就绪、写入是否幂等；
5. **消费侧**：读模型版本、`as_of` 口径、缓存元信息。

常用直查（控制面元数据）：

```sql
-- 最近的任务运行
SELECT run_id, job_id, status, window_start, window_end, rows_written, error, started_at, finished_at
FROM meta.job_runs ORDER BY run_id DESC LIMIT 20;

-- 当前水位
SELECT dataset, scope, watermark_time, updated_at FROM meta.watermarks;

-- 实际落库情况
SELECT trade_date, count(*) FROM cn_equity.daily_bar GROUP BY trade_date ORDER BY trade_date DESC LIMIT 10;
```

## 2. 凭证与权限

| 现象 | 判断 | 处置 |
|---|---|---|
| `MissingCredentialError` | 调用了一个未注入凭证的源 | 在 `HubConfig` 中补齐该源凭证；`from_config` 会跳过缺凭证的源 |
| 鉴权失败 / 401 / 403 | 凭证过期或权限不足 | 更新凭证；确认该账号具备对应接口权限 |
| 数据库连接失败 | DSN 或网络问题 | 检查 `DATABASE_*` / `FDP_DATABASE_HOST`；确认数据库可达 |
| 写入被拒（只读连接） | 只读账号用于写入 | 写入端与读取端使用各自的连接与授权；只读连接写入会被数据库拒绝 |
| SDK `schema_incompatible` | SDK 版本与 schema 修订区间不匹配 | 升级 SDK 或平台（见 [SDK §6](sdk.md)）；不静默降级 |

## 3. 限流与成本

| 现象 | 判断 | 处置 |
|---|---|---|
| `RateLimitTimeout` | 某源等待令牌超时 | 调大该源 QPS / 超时；先确认没有并发重复请求 |
| 源端返回 429 / 退避 | 触发源端动态限流 | 降低并发；等待退避自动重试完成 |
| 调用量异常偏高 | 缓存未命中或请求未合并 | 检查是否传了 `force=True`；确认批量接口走合并路径 |
| 多进程总量需要控制 | 接入层默认进程内限流 | 配置 `FDP_RATE_LIMITS` / `FDP_BUDGET_*` 启用跨进程共享配额 |
| `/v1/usage` 显示 `shared=false` | 缓存不可用（fail-open 降级） | 检查 Redis 可达性与 `FDP_REDIS_URL`；恢复后自动接管，采集不受影响 |

## 4. 数据缺口与水位

**先分清三种"没有数据"**：

1. **源端还没有**：A 股 15:00 收盘，源端发布通常发生在 15:00–16:00 之间；
   调度判定"今日已收盘"以 16:30（CST）为截止，避免抓到空数据；
2. **任务没有跑**：查 `/v1/jobs`——是否入队、失败原因、是否重试中；
3. **跑了但没写入**：同窗口重跑写入 0 行属正常幂等；但**源端 0 行**且窗口含交易日
   且标的在市 → 记为软失败 `EmptySourceWindow`（不推进水位、自动重试），按通道
   问题排查（出网代理 / 凭证 / 源端限流），而非数据缺口。

**水位语义**：水位只前进不后退；启动时从水位追平到最近已收盘交易日，
因此"停了一段再启动"会自动补数。需要重算历史时先明确影响范围，
再调整水位或写入窗口（属运维操作，不在默认流程内）。

**知识时间口径**：行情类数据默认以交易日收盘时刻（15:00 CST = 07:00 UTC）
作为知识时间——这是**稳定值**，保证重跑产生同一版本；物理入库时间另行记录。

**交易日历**：调度依赖交易日历判断"今日是否收盘"；日历源不可用会直接体现为
调度不入队，检查对应的日历查询是否正常。

## 5. Runtime 与调度

| 现象 | 判断 | 处置 |
|---|---|---|
| 启动即退出（码 2） | 配置非法 | 按日志修正：数据源必须显式且合法、起始日期须为 ISO 日期、调度表达式须为 5 段 cron（UTC）或 `interval:<秒>`、配额配置须合法 |
| 启动即退出（码 1） | 就绪检查未通过 | 按日志修复字典校验或数据库 schema（先运行迁移） |
| 服务在跑但无任务 | 未配置代码清单 / 水位已追平 / 源端未发布 | 确认配置了代码清单；查水位与运行记录；确认源端已发布 |
| 任务反复失败且错误为 `EmptySourceWindow` | 窗口含交易日但源端持续 0 行（通道异常被吞 / 标的退市或长期停牌） | 先排查源端通道（容器出网代理、凭证、限流）；确认属退市 / 长期停牌时按已知局限处置 |
| 调度未按预期触发 | cron 为 UTC、未考虑本地时区 | 将本地时间换算为 UTC 后重设 |
| 任务卡在运行中 | 进程被强杀后遗留 running 记录 | 优雅停机（stop 超时）会置为 `interrupted`，可重新提交（失败 / 中断不拦截去重）；SIGKILL 遗留的 running 会阻塞同数据集 / 范围的领取（与窗口无关，已知限制），需人工清理该运行记录（置 failed / dead） |

## 6. 迁移与 Schema

| 现象 | 判断 | 处置 |
|---|---|---|
| 找不到 `alembic.ini` | 部署镜像未打包迁移文件 | 镜像内显式拷贝 `alembic.ini` 与 `migrations/`，或用 `FDP_ALEMBIC_INI` / `FDP_ALEMBIC_SCRIPT_LOCATION` 指定 |
| 版本落后 / 校验失败 | 数据库不是最新版本 | 执行升级；升级可重复执行 |
| 字典改过但表没变 | 缺少迁移修订 | 字典变更必须新增迁移修订后升级 |
| 测试想跑破坏性迁移 | 默认被拒绝 | 显式设置 `FDP_TEST_DATABASE=1` 且必须指向开发库 |

## 7. 复权与跨源合成

- **指数请求复权被拒绝**：指数是编制结果序列，不存在价格复权概念。
  平台会显式报错而不是静默返回原始价，按提示改用 `adjust=None`；
- **原生复权不可信的源**：由 Router 以「原始价 + 因子」合成——需要配置因子源
  （默认 Tushare），未配置因子源时请使用 `adjust=None`；
- **因子源不可用**：先确认因子源凭证与限流状态；合成失败会显式报错而非近似替代；
- 结果中携带实际执行源与复权方式，排查时以 `df.attrs` 为准。

## 8. 消费侧（SDK / REST）

| 现象 | 判断 | 处置 |
|---|---|---|
| 数值与"最新"不符 | 读到的是历史版本 | 检查查询的 `as_of` 口径；确认是否需要最新态 |
| 换了数据源后结果变化 | 读模型未受影响属预期 | 源差异在 Canonical 层吸收；口径变化时读模型升语义版本 |
| 明细与汇总对不上 | 可能读到了缓存 | 用 `force=True` 刷新后复核；缓存携带 `cached / fetched_at` 元信息 |
| 找不到数据集 / 字段 | 契约未登记 | `GET /v1/datasets` 查数据目录；字段以字典为准 |
| 因子读取 404 / `factor_not_materialized` | 因子未物化 | 触发物化（`control.materialize` 或派生任务），读路径不做 lazy 回填 |
| `as_of_not_aligned` | 请求时点早于因子投影知识锚 | 用不早于 `computed_at` 的时点，或 pin 已注册的算法标识 |
| `inputs_stale` / `upstream_stale` | 输入滞后 / 上游因子升级未重算 | 按 `hint` 触发输入同步或上游重算 |
| 错误体看不懂 | 数据面错误为 RFC 9457 问题体 | 读 `type / title / detail / hint / request_id`；`hint` 给出下一步 |

## 9. 收集信息

仍无法定位时，请收集：启动日志、`/v1/jobs` 最近记录、`/v1/watermarks` 当前值、
复现查询的最小代码（含 `as_of` 与参数）、`request_id`（服务端可关联日志），再行排查。
