# 系统架构

> 本文描述系统的整体结构、分层与边界。
> 设计动机见 [系统理念](philosophy.md)；各组件的职责与用法见 [核心组件](components.md)。

## 1. 全景

```
                 ┌──────────────┐
                 │ Data Sources │   Tushare / Wind / iFinD / AkShare / Fuyao / BaoStock
                 └──────┬───────┘
                        │  （显式 source）
                  FinDataHub            接入层：唯一的源访问面
                  ├─ Adapter            各源适配器
                  ├─ Router             跨源合成（补全 / 复权 / 回退 / 溯源）
                  └─ 限流 · 缓存 · 计量
                        │
        ┌───────────────┼───────────────┐
        │               │               │
   Dictionary      Entity Registry    Storage
   数据契约          实体身份          Raw → Canonical → Read Model
        │               │               │
        └───────────────┼───────────────┘
                        │
                  Derived Engine        派生：算法登记 / as-of 输入 / 重述台账
                        │
                    Access              访问面：Raw / Factor 读取（PIT + 复权口径组合）
                        │
                    Read Models         语义版本化的只读出口（mart.*_v*）
                        │
        ┌───────────────┼───────────────┬───────────┐
        │               │               │           │
       SDK            REST           Export      (MCP…)
```

两个定位要点：

- **平台是数据基础设施，不是应用后端**。主体是契约、身份与时间语义、存储与快照，
  以及控制面；API 只是出口。
- **接入层与平台层是两个包**：接入层（`fin_data_hub`）做源适配与多源合成，
  平台层（`fin_data_platform`）做契约、身份、存储与派生。

## 2. 层间依赖与写入边界（硬约束）

1. **单向依赖**：`接入层 → 平台写入端 → Canonical → Access（Raw/Factor 读取）→ Read Model → 消费适配器`；
2. **禁止**：平台直连数据源 Adapter；管理台直连数据库；**绕过访问面（Access）直读 Raw / Canonical 物理表**；
3. **写入面**只有平台内部写入端（采集、派生计算、文件导入、质量结果），
   按最小授权拆分读写连接；对外一律只读。

## 3. 平面与职责

| 平面 | 内容 | 说明 |
|---|---|---|
| **Control Plane** | Runtime（调度 / 分发 / 执行）、任务定义与运行记录、水位、质量结果、算法登记与重述台账 | `meta` schema + 常驻进程 |
| **Data Plane** | Entity Registry、DataPanel（Raw → Canonical → Read Model）、TimescaleDB | 分层由字典声明 |
| **Access Plane** | Raw 读取（PIT + 复权等口径组合）、Factor 读取（严格 as-of 对齐） | 内部接口层：派生计算与消费出口共用同一实现，读不写库 |
| **Consumption Plane** | SDK / REST（含管理 API 与 WebUI）/ 批量导出 / 未来的 MCP 等 | 只读适配器，不改变数据语义；回填与物化仅提交控制面意图 |

## 3.1 访问面（Access）

- **职责**：把 Canonical 的原始存储（原始价 + 复权因子等）组合成"可直接计算"的规范化数据；
  复权等口径组合只在这里实现一次（与数据源的 Router 口径一致），派生引擎与消费出口不再重复；
- **PIT 严格**：`as_of` 显式（知识时间过滤 + 每业务键最新版本）；不做 lazy 回填，读路径不写库；
- **因子对齐**：物化因子为单份投影（知识锚 = 物化时间戳），请求时点早于该锚点时报
  `as_of_not_aligned`，而不是返回不一致的结果；
- **意图分离**：缺数据的补救方式是**控制面意图**（回填 / 物化任务，幂等、可审计），
  客户端不持写权限。

## 4. 数据分层

| 层 | 职责 | 写入方 | 读者 |
|---|---|---|---|
| **Raw** | 源端原始响应（字段与语义不变），审计 / 重放 / 对账，append-only | 采集 | 审计与对账工具 |
| **Canonical** | 归一化统一表：标准字段 / 单位 / 枚举 / 代码 + PIT 字段 | 采集 + 派生 | 派生计算、质量检查、平台内部（**经访问面**） |
| **Read Model** | 面向消费的稳定接口：字段与口径冻结、语义版本、as-of 视图、权限裁剪 | 由 Canonical 派生 | **SDK / REST / 管理台 / 导出（默认消费入口）** |

规则：

1. 消费侧只读 Read Model；2. 换源不影响消费侧；3. 读模型**语义版本化**（`_v1` / `_v2`）：
   新增字段、扩展枚举不升版本；字段含义、口径、单位变化必须升主版本，新旧并存过渡后弃用。

## 5. 存储与 PIT

**Schema 分层**：

| Schema | 内容 |
|---|---|
| `<domain>` | Canonical 标准表，与数据域同名（如 `cn_equity`、`cn_fund`） |
| `ref` | 参照数据：实体、代码履历、关系、外部标识、关系词表 |
| `mart` | Read Model（语义版本视图 / 表函数） |
| `meta` | 控制面元数据：任务定义、依赖、运行记录、水位 |
| `raw` | 源端原始留存（规划） |

**表形态**由数据集的 PIT 类别决定：

| 形态 | 适用 | 语义 |
|---|---|---|
| 时序事实（hypertable） | 行情、复权因子、净值 | 按事件时间分区 + 压缩 |
| 版本化时序（hypertable） | 财务、公司事件 | 按知识时间分区，append-only |
| 属性区间（SCD2） | 实体属性、指数成分、生命周期 | 闭区间，as-of 还原 |
| 快照 | 指数权重（月度） | 业务键 + 日期唯一 |

**PIT 双轴**：事件时间与知识时间分离；`as-of` 查询 = "知识时间 ≤ as_of，
按业务键取最新版本"；Canonical 不落 `is_latest` 列（它随刷新而变，不属于事实）。

**幂等**：写入以物理键（业务键 + 知识时间 + 版本）判重，重复执行不产生新行；
重跑同一交易日得到同一份数据。

**缓存（横切）**：L1 进程内 + L2 Redis，非权威、可清空重建、fail-open；
键含 PIT 维度与域代际，同步完成按域失效；跨进程 single-flight 防击穿。

**迁移**：版本化迁移（Alembic），基线由数据字典生成，升级可重复、可回滚；
字典变更必须新增迁移修订。

## 6. 控制面：Runtime

Runtime 是常驻控制面进程，负责"按正确的时间、正确的顺序、可追溯地跑任务"：

- **角色可拆**：`all`（单机默认）/ `scheduler`（只调度与分发）/ `worker`（只执行），
  两者仅凭数据库协调，因此可水平拆分；
- **任务模型**：任务定义（声明式注册）→ 运行记录（状态机）→ 水位（增量进度）；
- **依赖门控**：子任务只在父任务成功后入队；
- **交易日历与发布窗口**：区分"已收盘"与"源端已发布"，避免抓到空数据；
- **重试与补数**：失败自动重试；水位驱动窗口推进，启动即追平历史缺口；
- **可观测**：运行记录可查询（任务 / 窗口 / 耗时 / 结果），健康检查在启动时
  校验字典与 schema，配置错误快速失败。

## 7. 幂等与版本

| 对象 | 版本维度 | 说明 |
|---|---|---|
| 数据写入 | 物理键（业务键 + 知识时间 + 版本） | 重跑不产生新版本 |
| 读模型 | 语义主版本（`_v1` / `_v2`） | 契约变化时升级，新旧并存 |
| 派生算法 | 算法标识（带版本） | 升级新增标识，旧实现永久保留 |
| 排队任务 | 幂等键 | 仅派生（算法标识）与读模型构建（语义版本）带版本维度 |

## 8. 部署拓扑

- **形态**：单机 Docker Compose（TimescaleDB + Redis + 一次性迁移 + 控制面），
  单镜像多入口（角色以参数区分，可拆 scheduler / worker 进程）；K8s 不在当前范围；
- **启动顺序**：数据库就绪 → 迁移成功 → Runtime 启动；健康检查基于就绪检查；
- **库模式**：契约、身份、存储与迁移均可作为纯库使用，不依赖常驻进程；
- **凭证**：一律由调用方 / 环境注入，不进入镜像与仓库；
- **读写分离**：写入端与只读端使用不同的数据库连接与授权（只读角色 `fdp_ro`：
  `mart`/`ref`/数据域 `SELECT`，不含 `raw`/`meta`；矩阵见配置手册）。
