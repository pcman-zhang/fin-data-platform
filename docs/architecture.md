# 系统架构：结构与运行机制

> 本文写给需要**理解或扩展**平台的金融系统开发者：先给出分层与边界，
> 再完整走一遍"一条数据的一生"，最后解释 PIT、幂等、控制面与部署的机制。
> 设计动机见 [系统理念](philosophy.md)；各组件职责见 [核心组件](components.md)。

## 1. 全景

```
                 ┌──────────────┐
                 │ Data Sources │   Tushare / Wind / iFinD / AkShare / Fuyao / BaoStock
                 └──────┬───────┘
                        │  （显式 source）
                  FinDataHub            接入层：唯一的源访问面
                  ├─ Adapter            各源适配器
                  ├─ Router             跨源合成（补全 / 复权 / 回退 / 溯源）
                  └─ 限流 · 缓存 · 计量
                        │
        ┌───────────────┼───────────────┐
        │               │               │
   Dictionary      Entity Registry    Storage
   数据契约          实体身份          Raw → Canonical → Read Model
        │               │               │
        └───────────────┼───────────────┘
                        │
                  Derived Engine        派生：算法登记 / as-of 输入 / 重述台账
                        │
                    Access              访问面：Raw / Factor 读取（PIT + 复权口径组合）
                        │
                    Read Models         语义版本化的只读出口（mart.*）
                        │
        ┌───────────────┼───────────────┬───────────┐
        │               │               │           │
       SDK            REST           Export      (MCP…)
```

两个定位要点：

- **平台是数据基础设施，不是应用后端**。主体是契约、身份与时间语义、存储与快照，
  以及控制面；API 只是出口。
- **接入层与平台层是两个包**：`fin_data_hub` 做源适配与多源合成，
  `fin_data_platform` 做契约、身份、存储与派生。平台层不直连数据源。

## 2. 层间依赖与写入边界（硬约束）

```
接入层 → 平台写入端 → Canonical → Access（Raw / Factor 读取）→ Read Model → 消费适配器
```

1. **单向依赖**：上层不得反向依赖下层；消费侧不得绕过 Access 直读 Raw / Canonical 物理表；
2. **写入面唯一**：只有平台内部写入端（采集、派生计算、文件导入、质量结果）可以写库；
   管理台与 SDK **不直连数据库写**；
3. **读写连接分离**：写入端与只读端使用不同的数据库连接与授权——
   只读角色只被授权 `mart` / `ref` / 数据域 `SELECT`，不含 `raw` / `meta`；
   读连接另配语句超时（默认 30s），写端与批量导出不受限；
4. **回填与物化不是写操作，是意图**：客户端只能提交控制面意图（幂等、可审计），
   由 Runtime 执行；客户端永不持有写权限。

## 3. 平面与职责

| 平面 | 内容 | 载体 |
|---|---|---|
| **Control Plane** | Runtime（调度 / 分发 / 执行）、任务定义与运行记录、水位、质量结果、算法登记与重述台账、配额计数 | `meta` schema + 常驻进程 + Redis 共享计数 |
| **Data Plane** | Entity Registry、DataPanel（Raw → Canonical → Read Model）、TimescaleDB | 数据域 / `ref` / `mart` schema |
| **Access Plane** | Raw 读取（PIT + 复权等口径组合）、Factor 读取（严格 as-of 对齐） | 库内接口层：派生计算与消费出口共用同一实现，读不写库 |
| **Consumption Plane** | SDK / REST（含管理 API 与 WebUI）/ 批量导出 / 未来的 MCP 等 | 只读适配器，不改变数据语义 |

## 4. 一条数据的一生（端到端走查）

以"某只股票的日线行情"为例：

1. **触发**：Runtime 的调度器按任务定义（`sync.cn_equity.daily_bar.<code>`）计算到期窗口，
   交易日历判定"已收盘且源端已发布"后生成运行记录，入队等待执行；
2. **取数**：执行器经接入层调用数据源（显式 `source`，如 `tushare`）。
   接入层完成：限流（每源令牌桶）→ 缓存查找 → 适配器请求 → 归一化
   （统一代码模型与输出 schema）→ 必要时 Router 合成（补字段 / 复权 / 回退），
   结果携带 `source / cached / fetched_at` 等元信息；
3. **写入**：平台写入端按数据字典校验并**幂等写入** Canonical 表
   （物理键 = 业务键 + 知识时间 + 版本；重复执行不产生新行），同时推进水位；
   源端原始响应可留存在 Raw 层（审计 / 重放 / 对账，append-only）；
4. **质量**：质量任务按字典规则扫描 Canonical（`unique` / `not_null` / `range` /
   `expression` / `jump` / 完整性覆盖率 / 时效性 / 跨源对账），
   结果 append-only 写入 `meta.quality_results`；
5. **派生**（可选）：派生引擎以**访问面**读取的规范化数据为输入，
   按算法登记（`algorithm_id`）计算因子，物化为单份投影；
6. **发布**：读模型（`mart` 下语义版本化视图 / 表函数）从 Canonical 派生，
   as-of 语义原生；同步完成后按域推进代际，缓存随之失效；
7. **消费**：SDK / REST / 导出只读读模型（或经数据面 PIT 行查询访问 Canonical 读视图）；
   每个数值都能回答"从哪来（source）、何时可知（知识时间）、用什么算法算的（算法标识）"。

## 5. PIT 机制详解

### 5.1 双时间轴

| 时间 | 含义 | 用途 |
|---|---|---|
| 事件时间 | 数据描述的事情何时发生（如交易日、报告期） | 分区、范围查询、对齐 |
| 发布时间 | 源端何时公告 | 溯源与对账 |
| 知识时间 | 市场何时可知（通常等于发布时间，或平台的入库判定） | **as-of 过滤的唯一主轴** |
| 入库时间 | 数据何时进入本平台 | 审计与重放 |

### 5.2 版本追加与 as-of 查询

- 写入不覆盖：修正 / 重述以**新版本**追加，旧版本永久保留；
- `as-of` 查询的执行语义：

  ```
  知识时间 ≤ as_of  →  按业务键分组  →  每组取版本号最大的一行
  ```

- Canonical 不落 `is_latest` 列——它随刷新而变，属于视图状态而非事实；
- 数据面 PIT 行查询支持 `version_mode=latest / as_of / history`，
  并可指定 `as_of_policy=knowledge/publish` 与 `fallback_mode=strict/allow`
  （发布时刻缺失时决定报错或回退）；
- 属性类数据（名称、类型、指数成分等）用 SCD2 闭区间存储，as-of 时还原当时值。

### 5.3 读模型与代际

- 读模型是**面向消费的稳定接口**：字段与口径冻结、语义版本（`_v1` / `_v2`）、
  as-of 视图、权限裁剪；新增字段不升版本，含义 / 口径 / 单位变化必须升主版本，
  新旧并存过渡后弃用；
- 因子物化会写入**数据代际**（data generation），消费侧可用
  `GET /v1/algorithms/generations` 观测各投影当前代次；
- 缓存的**域代际**（`fdh:gen:{domain}`）随同步 / 物化推进：缓存键携带域代际，
  代际推进即自然失效，无需扫描删键。

### 5.4 因子对齐（访问面）

- 物化因子是单份投影，携带**知识锚**（物化时间戳）；
  请求时点早于锚点时报 `as_of_not_aligned` 结构化异常，而不是返回不一致结果；
- `materialize: none` 的因子按需计算（输入严格 as-of）；`materialize: latest`
  在首次物化前无投影可读——物化是控制面意图，需显式触发；
- 复权口径下缺复权因子的行（NULL）不参与计算。

## 6. 存储与 schema

| Schema | 内容 |
|---|---|
| `<domain>` | Canonical 标准表，与数据域同名（如 `cn_equity`、`cn_fund`） |
| `ref` | 参照数据：实体、代码履历、关系、外部标识、关系词表、交易日历 |
| `mart` | Read Model（语义版本视图 / 表函数） |
| `meta` | 控制面元数据：任务定义、依赖、运行记录、水位、质量结果、算法登记 |
| `raw` | 源端原始留存（规划） |

**表形态**由数据集的 PIT 类别决定：

| 形态 | 适用 | 语义 |
|---|---|---|
| 时序事实（hypertable） | 行情、复权因子、净值 | 按事件时间分区 + 压缩 |
| 版本化时序（hypertable） | 财务、公司事件 | 按知识时间分区，append-only |
| 属性区间（SCD2） | 实体属性、指数成分、生命周期 | 闭区间，as-of 还原 |
| 快照 | 指数权重（月度） | 业务键 + 日期唯一 |

**迁移**：版本化迁移（Alembic），基线由数据字典生成；升级可重复、可回滚；
字典变更必须新增迁移修订，CI 校验 schema 与字典一致。

## 7. 控制面：Runtime

Runtime 是常驻控制面进程，负责"按正确的时间、正确的顺序、可追溯地跑任务"：

- **角色可拆**：`all`（单机默认）/ `scheduler`（只调度与分发）/ `worker`（只执行），
  两者仅凭数据库协调，因此可水平拆分；
- **任务模型**：任务定义（声明式注册）→ 运行记录（状态机）→ 水位（增量进度）；
- **依赖门控**：子任务只在父任务成功后入队（如因子物化依赖上游数据同步）；
- **幂等**：排队任务带幂等键（同窗口 / 同算法版本的意图重复提交被忽略）；
- **交易日历与发布窗口**：区分"已收盘"与"源端已发布"，避免抓到未完成的当日数据；
- **重试与补数**：失败自动重试（指数退避）；水位驱动窗口推进，启动即追平历史缺口；
- **可观测**：运行记录（任务 / 窗口 / 耗时 / 结果）、健康检查（启动时校验字典与 schema）。

## 8. 幂等与版本

| 对象 | 版本 / 判重维度 | 说明 |
|---|---|---|
| 数据写入 | 物理键（业务键 + 知识时间 + 版本） | 重跑不产生新版本 |
| 读模型 | 语义主版本（`_v1` / `_v2`） | 契约变化时升级，新旧并存 |
| 派生算法 | 算法标识（带版本） | 升级新增标识，旧实现永久保留 |
| 排队任务 | 幂等键 | 派生与读模型构建带算法 / 语义版本维度 |

## 9. 部署拓扑

- **形态**：单机 Docker Compose（TimescaleDB + Redis + 一次性迁移 + 授权 +
  控制面 + 服务），单镜像多入口（角色以参数区分，可拆 scheduler / worker）；
- **启动顺序**：数据库就绪 → 迁移成功 → 授权脚本 → Runtime / 服务启动；
  健康检查基于就绪检查（数据库 / 字典 / schema 版本）；
- **库模式**：契约、身份、存储与迁移均可作为纯库使用，不依赖常驻进程；
- **凭证**：一律由调用方 / 环境注入，不进入镜像与仓库；
- **缓存与配额**：Redis 为 L2 缓存与跨进程配额计数的共享层，非权威、可清空重建、
  故障时 fail-open（详见 [配置手册](configuration.md)）。
