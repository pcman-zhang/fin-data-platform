> 结构与依赖见 [系统架构](architecture.md)；配置方法见 [配置手册](configuration.md)；
> 动手扩展的完整流程见 [扩展开发](extending.md)。

## 1. FinDataHub（接入层）✅

**定位**：唯一的源访问面。所有数据源调用都经过它，平台其余部分不接触供应商 SDK。

**职责**

- **适配**：按资产类型与接口能力适配各数据源（Tushare / Wind / iFinD / AkShare / Fuyao / BaoStock）；
- **归一**：统一代码模型（`symbol.VENUE`，如 `600000.SH`、`000001.OF`）与统一输出 schema；
- **Router（跨源合成）**：以请求的 `source` 为主源——缺字段时从补充源 coalesce 补全、
  缺复权能力时以「原始价 + 因子」合成、主源失败时按配置回退，结果携带溯源；
- **限流**：每源独立的令牌桶（QPS），等待超时抛出明确错误；平台部署下可升级为
  跨进程共享窗口计数（见 [配额](#10-quota平台配额)）；
- **缓存**：进程内 TTL + LRU + 字节预算，`force=True` 跳过缓存；
- **计量**：按源统计调用次数与估算成本、预算告警，支持回调导出做跨进程汇总。

**边界**：只做归一化与合成，**不落数据**；不决定数据存到哪张表；不做业务口径判断。

**关键概念**：`source` 显式且语义不可变（补全与回退不改变主源标注）；
按需触发补充调用（成本最小化）；结果 `df.attrs` 携带 `source / cached / fetched_at`。

**扩展点**：新增数据源 = 实现适配器并声明能力（见 [扩展开发 §1](extending.md#1-新增数据源适配器)）。

**代码**：`src/fin_data_hub/`（`facade.py` 门面、`routing.py` 路由、`sources/` 适配器、
`ratelimit.py`、`cache.py`、`usage.py`）

### 各源支持范围

逐源状态、已知问题与对账结论见 [数据源](data-sources.md)；下表为能力速查。

| 能力 | Tushare | AkShare | Wind | iFinD | Fuyao | BaoStock |
|---|---|---|---|---|---|---|
| 日线行情 | ✅（含 qfq/hfq） | ✅ 股票 / ETF / LOF / 指数 | ⚠️ 单代码逐次 | ⚠️ 仅指数 | ✅ 单标的（长窗口分块） | ✅ SH/SZ |
| 快照 | — | ✅ 股票 / ETF / LOF（指数—） | ✅ 单次批量 | — | ✅ 批量 | — |
| 场外基金净值 | ✅ | ✅ | — | ✅ 多基金合并 | — | — |
| 参考数据 | ✅ | — | — | — | ✅ 列表类 | — |
| 标的 / 指数成分 / 财务 / 事件 | ✅ | — | — | — | — | — |
| 交易日历 | ✅ | ✅ | — | — | ✅（一年窗口） | — |
| 宏观 / 债券等特色接口 | — | — | ✅ | ✅ | — | — |

限制说明：

- **Wind**：日线不接受 `period` 参数；K 线为单代码接口，多代码由库逐次调用；
- **iFinD**：K 线目前仅支持指数；自然语言类接口支持多标的 / 多指标聚合，
  由库合并为单次调用，单次请求标的数有安全上限；
- **AkShare**：无参考数据接口；快照为全市场 spot 接口（一次调用后按代码本地过滤，
  指数暂不支持）；行情 / 净值为单标的形式，批量请求由库自动拆分；
- **BaoStock**：仅支持沪深两市（`sh.` / `sz.` 前缀，含指数）；原生复权不列入可信源；
  连接断开自动重新登录；
- **Tushare**：行情按资产类型路由（股票 / ETF-LOF / 指数使用不同接口）；
  指数不存在价格复权概念，请求指数复权会被显式拒绝而非静默忽略；
- **Fuyao**：快照能力主力来源；原生复权序列不可用，请求复权时由 Router 组合
  「原始价 + 因子」合成（需配置因子源）；
- **Wind / iFinD 的宏观与债券等特色接口**：适配器层方法已具备，平台门面尚未开放
  （预留接口），当前仅经接入层库直接使用。

## 2. Dictionary（数据契约）✅

**定位**：机器可读的数据契约，是"我们有哪些数据、以什么口径存在"的唯一事实来源。

**职责**

- 数据集（DataPanel）登记：字段 / 类型 / 单位 / PIT 角色 / 主键 / 粒度 / SLA / 覆盖率；
- 质量规则与血缘（上游数据集与转换）；
- 源映射（每个 canonical 字段来自哪个源字段）与采集入口声明；
- 派生登记（算法标识、实现路径、输入）；
- **Schema First**：数据库 DDL、迁移基线、读模型与生成式文档由契约派生或强校验。

**边界**：定义"数据是什么"，不做数据搬运；不承载运行状态（运行、质量结果在控制面）。

**关键概念**：字段兼容不等于语义兼容；契约变更走 CI 校验与版本评审。

**扩展点**：新增数据集 = 在 `dictionary/` 增加声明（字段 / 主键 / 质量 / 血缘 / 源映射），
再生成迁移；校验入口见 [扩展开发 §2](extending.md#2-新增数据集字典条目)。

**代码**：`src/fin_data_platform/dictionary/`（含 `ref/` 参照数据与各数据域目录）

## 3. Entity Registry（实体身份）✅

**定位**：回答"数据说的是谁"——实体身份、关系与外部标识的唯一权威。

### 为什么需要这一层

把代码当作身份，是多源数据里最容易犯、也最昂贵的错误。四个现实问题决定了
必须有独立的一层来管理身份：

1. **一串代码不是一个人**。代码会变更（更名、市场迁移）、会被复用（退市后原代码
   交给新标的）；同一实体在不同源有不同写法（带后缀 / 裸代码 / 源内部编号）。
   用代码做跨源主键，历史一断，所有拼接都错。
2. **一家公司不等于一只证券**。同一家发行主体可能同时拥有 A 股、B 股、H 股、
   可转债等多只证券；而财务、股东、公司事件说的是**公司**，
   行情、成分、复权说的是**证券**。若不区分，财务数据就会挂到某一只股票上，
   或跨源永远对不上。
3. **代码之外还有关系信息**。母子公司、控制关系、发行关系构成图结构，
   查询与治理都需要词表约束，而不是散落在各数据集的自由文本字段里。
4. **跨源对齐需要稳定外部标识**。ISIN / LEI / 统一社会信用代码等是跨源、跨市场
   对齐的锚点；Ticker 会变，外部标识相对稳定。

### issuer 与 listing：为什么要分开

| 概念 | 含义 | 挂载的数据 |
|---|---|---|
| **issuer（发行主体）** | 法律主体：工商注册的公司 / 机构 | 财务报表、股东、公司事件、主体属性（存续状态等） |
| **listing（上市实体）** | 证券市场中的交易标的：股票、ETF、基金、指数、债券等 | 行情、复权因子、指数成分、净值 |
| 关系（如 `issued_by`） | listing → issuer 的发行关系 | 连接两侧数据的桥梁 |

分开的直接收益：

- **口径正确**：公司级数据只挂 issuer 一次，不因多个证券而重复；
- **可扩展**：同一主体新增上市地 / 新证券时，只增加 listing 与关系，历史不受影响；
- **可追溯**：分红、股本这类"两侧都有"的数据，经关系落位到正确的一侧，
  跨源核对时有共同锚点。

非发行类的实体（指数、篮子等）同样登记为实体，只是不走 issuer 关系。

### 其余设计要点

- **稳定主键**：实体一经登记，拥有不随代码变化的稳定标识，所有数据集引用它；
- **全市场登记**：全局任务 `sync.reference.market_registry` 从基础信息源同步身份
  （股票 / ETF / 场外基金 / 指数，含退市）与上市 / 退市区间
  （`cn_equity.listing_lifecycle`）；启动即首灌，可配 `FDP_REGISTRY_SCHEDULE`
  周期刷新，也可在任务页或 `POST /v1/jobs/trigger` 手工触发（幂等）；
- **PIT Universe**：管理 API `GET /v1/entities/universe?as_of=` 按交易状态区间
  返回某历史日在市标的（可选 `knowledge_as_of` 严格 PIT）；
- **代码履历**：代码变更与复用写入履历，旧代码仍可解析回同一实体；
- **关系是词表驱动的**：关系类型必须先登记，单向存储、双向查询由词表元数据生成；
- **外部标识**：登记 ISIN / FIGI / CUSIP / SEDOL / LEI / USCC 等跨源锚点
  （不含 Ticker——Ticker 是代码，属履历）；
- **身份与状态分离**：交易状态（上市 / 停牌 / 退市）是数据、不是身份；
- **属性保留历史**：名称、类型等属性按 SCD2 保存区间，任意时点可还原当时值。

**边界**：不含交易状态（属数据集）；不含数据目录（属字典）；不维护源映射；
不含算法登记（属派生引擎）。

**代码**：`src/fin_data_platform/registry/`（身份、代码履历、关系、外部标识、PIT Universe）

## 4. Storage（PIT 存储）✅

**定位**：把契约与时间语义落到数据库，并保证幂等与可回放。

**职责**

- 按字典生成 schema（表、分区、压缩、读模型）；
- 幂等写入：物理键判重，重跑不产生新版本；
- as-of 与最新态读取、实体读模型；
- 版本化迁移（升级 / 回滚 / 版本校验）。

**边界**：不定义口径（字典定义）；不做源适配（接入层负责）；消费侧不直读物理表。

**关键概念**：Raw → Canonical → Read Model；事件时间与知识时间分离；
hypertable 分区与压缩；SCD2 区间；读模型语义版本。

**代码**：`src/fin_data_platform/storage/`（schema 生成、写入与读取、读模型、迁移、
只读角色授权 `grants.py`）

### 源侧读取（日历与状态感知）

**定位**：源层读取入口——直连 Hub 取行情，叠加落库参照数据（交易日历 + 每日状态），
把「交易日 × 标的」补齐为预期行并标注状态；用于缺口检查、对账与状态感知消费。

| status | 含义 | 数值 |
|---|---|---|
| `ok` | 交易日且行情存在 | 正常值（盘中停牌有成交时以行情存在为准） |
| `suspended` | 交易日、停牌且无行情 | NaN（正常无交易，不是缺失） |
| `missing` | 交易日、非停牌但无行情 | NaN（数据质量问题，不填充） |

非交易日不产出行（"无需有"，不是缺失）。组合全部在 pandas 内完成，SQL 不 JOIN；
实体身份须先在注册表建立（未注册代码显式报错）。

**代码**：`src/fin_data_platform/source/`（`read_bars_with_status`）

## 5. Runtime（控制面）✅

**定位**：常驻控制面进程——"按正确的时间、正确的顺序、可追溯地运行任务"。

**职责**

- **调度**：按数据域与窗口生成任务，交易日历感知，启动即追平历史缺口；
- **分发与执行**：任务按依赖门控入队，工作池并发执行，背压保护；
- **状态与追溯**：任务定义、依赖、运行记录、水位持久化，可查询；
- **健康检查**：启动时校验字典与 schema，配置错误快速失败。

**边界**：编排与状态管理，不含业务口径；派生逻辑属派生引擎；消费出口属消费层。

**关键概念**：角色可拆（单机 / 调度 / 执行，仅凭数据库协调）；幂等键；
水位单调推进；失败重试与断点补数。

**扩展点**：新增周期任务 = 注册任务定义（`kind` / 幂等键 / 依赖 / 调度），
见 [扩展开发](extending.md) 与现有 `ingestion/tasks.py` 示例。

**代码**：`src/fin_data_platform/runtime/`（入口、角色、任务仓储、日历、窗口、触发、健康）
与 `src/fin_data_platform/ingestion/`（采集写入与配置装配）

## 6. Quality（数据质量）✅

**定位**：把数据字典的质量规则**实例化执行**，产出可追溯的每日质量报告——
每个异常都能回答「哪条规则、哪个窗口、哪些行」。

**职责**

- **规则执行**：字典 `quality` 规则逐条编译为 SQL 检查——`unique`（物理键）/ `not_null` /
  `range` / `enum` / `expression`（受限表达式）/ `jump`（相邻行跳变）/
  `reconcile`（对账目标共享键存在性）；值检查按业务键**最新版本**执行；
- **完整性**：`coverage` 期望集合（在市标的，停牌感知）× 交易日 vs 实际行，
  输出覆盖率与逐日断点；
- **时效性**：`update_sla` + 最新数据日 → 滞后交易日数；
- **跨源对账**：小样本实拉（基准源 vs 对照源）——原始价一致与复权因子归一化比较，
  输出重叠样本、最大差与容差；
- **报告与追溯**：结果 append-only 写入 `meta.quality_results`（运行 × 数据集 × 检查），
  含窗口 / 严重级 / 违例数 / 样本 / 指标；经管理 API 与 WebUI「质量」页出每日报告。

**边界**：只读扫描与报告，不修改数据；外部通知渠道不在本层；
规则文本归数据字典（本层只执行，不发明口径）。

**扩展点**：新增质量规则 = 在字典声明 + 在规则编译层注册检查类型（如有新形态），
见 [扩展开发 §4](extending.md#4-新增质量检查类型)。

**代码**：`src/fin_data_platform/quality/`（规则编译、扫描执行、结果存储、任务挂载）

## 7. Derived Engine（派生引擎）✅

**定位**：派生指标（因子）的可复现、可审计计算与登记——平台的**因子库**形态。

**职责**

- 算法以代码实现并登记（带版本的稳定标识；升级新增标识、旧实现永久保留）；
- 输入一律来自**访问面**的规范化数据（复权等口径已组合，不用原始 OHLCV）；
- as-of 输入防前视；批量重算；依赖图决定执行顺序与重算范围；
- 物化：因子全序列的单份投影（可重建、代次切换）；读取严格对齐、不对齐报错；
- 升级与重述台账：记录生效日与原因。

**边界**：列级口径（复权、单位、跨源对齐）归**访问面**，不属于派生；
不存派生结果的多版本；不做因子挖掘与策略研究（属消费侧）。

**扩展点**：新增因子 = 实现函数 + `@register(algorithm_id=..., version=...)` +
字典声明输入输出，见 [扩展开发 §3](extending.md#3-新增派生算法因子)。

**代码**：`src/fin_data_platform/derived/`（`registry.py` 登记、`engine.py` 计算与物化、
`factors.py` 内置因子、`consistency.py` 一致性校验）

## 8. Access（访问面）✅

**定位**：Canonical 与消费方之间的**统一读取层**——把"存起来的原始数据"组合成
"可直接计算的数据"。

**职责**

- **Raw 读取**：PIT（`as_of` / 版本）+ **口径组合**（复权、单位、跨源优先级），
  缺省口径由数据字典声明（行情默认**后复权**——历史值不随新除权事件漂移；
  前复权可显式请求，用于与现价对比；指数类无复权）；
- **对齐读取（可选）**：`align_calendar` 按字典 `coverage.expected_dates.calendar`
  与按域约定的状态数据集（`{domain}.daily_status`）补齐「交易日 × 标的」预期行，
  标注 `status`（`ok` / `suspended` / `missing`）与停牌 / ST 标志；非交易日无行、
  缺行不填充（null→NaN）；日历与状态同一 `as_of` 严格 PIT；
- **Factor 读取**：物化投影严格对齐知识锚，`materialize: none` 的因子按需计算；
  不对齐报结构化异常，不做 lazy 回填；
- **时序查询**：范围序列 / 重采样 / 缺口策略 / 窗口算子 / vintage（版本历史）/
  asof join，与因子和消费出口共用同一实现；
- **单一实现**：派生计算与消费出口共用同一实现，复权逻辑不出现第二份；
- **读不写库**；回填 / 物化是控制面意图（Runtime 执行，可审计）。

**边界**：只读；不改变数据语义；不是对外契约层（对外契约见 Read Model 与
[SDK 文档](sdk.md)）。

**代码**：`src/fin_data_platform/access/`、`src/fin_data_platform/query/`、
`src/fin_data_platform/panel/`

## 9. Read Model 与消费层 ✅

**定位**：对外只读出口；消费适配器不承载平台语义。

**形态**

- **Read Model**：`mart` 下语义版本化的视图 / 表函数，as-of 语义原生（默认消费入口）；
- **SDK**：三个读面（Raw / Factor / Read Model）+ 控制面意图面；
  直连模式（direct mode）无需经过服务；契约见 [SDK 文档](sdk.md)；
- **REST**：SDK 的薄封装（管理面 + 数据面：PIT 行 / Raw / Factor）；
- **批量导出**：异步导出（Parquet / Arrow），分块写出、产物经共享卷下载；
- **管理 API / WebUI**：平台治理界面（数据集字典、实体注册表、任务与水位、质量报告、
  同步触发、配额与成本）——FastAPI + SPA，同镜像 `service`，默认仅本机。

**边界**：只读；不改变数据语义；权限按数据集裁剪。

**代码**：`src/fin_data_platform/sdk/`、`api/`、`export/`、`web/`

## 10. Quota（平台配额）✅

**定位**：把接入层的进程内限流与计量升级为**跨进程共享口径**，防止多进程部署下
总量超配、成本失控。

**机制**

- **共享限流**：固定窗口计数（原子 `INCRBY` + 窗口 TTL，键 `fdh:quota:rate:<source>`），
  多进程按源总量不超配；窗口缺省 `burst / rate`（持续速率 ≈ `rate`）；
- **预算与告警**：Hub 台账逐条回调写入共享计数（调用数 / 成本微单位 / 告警触发计数）；
- **fail-open**：缓存不可用时回退进程内限额与本地计量，采集不阻塞；恢复后自动接管；
- **查询**：`GET /v1/usage` 按源返回今日用量、预算、派生告警与限流配置；
  WebUI「总览」页有「配额与成本」卡片。

**边界**：计数是可重建的运行时状态（权威数据仍在数据库）；
配额不改变数据语义，只约束调用行为。

**配置**：`FDP_RATE_LIMITS` / `FDP_BUDGET_*`（见 [配置手册 §6.7](configuration.md)）。

**代码**：`src/fin_data_platform/quota/`

## 11. Cache（缓存层）✅

**定位**：L1 进程内 + L2 Redis 的分层缓存设施（**非权威**）；平台读取路径可选接入
（示例见 [配置手册 §5](configuration.md)），配额共享计数与代际失效钩子已在使用。

**机制**

- 键结构 `fdh:{domain}:{panel}:g{generation}:{pit}:{params_hash}`——
  PIT 维度必填（`as_of` 与 `knowledge_time` 二选一），域代际递增即批量失效；
- 跨进程 single-flight 防击穿（L2 锁）；L2 故障 fail-open（直读权威层）；
- 共享计数（配额）也走 L2，但语义上属于运行时状态而非缓存数据。

**代码**：`src/fin_data_platform/cache/`
