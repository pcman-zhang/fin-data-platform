# 管理型 WebUI 信息架构与权限模型

> 状态：评审中·**低优先级（暂不冻结）**——实现期 REST/SDK 接口可能调整，待接口稳定后再评估定稿 | 关联：doc-10 §1.3、doc-12（REST 契约）、doc-11（字典）、doc-15（认证与授权，暂不制作）、TASK-3.1（AC#9）/ TASK-3.8
> 第 2 稿变更：按**个人平台**定位收敛——认证与授权分离至 doc-15（暂不制作）；首期 WebUI 仅本机访问、无账号体系；**事件日志不保留**；通知渠道分离至 doc-16（暂不制作）；保留高风险操作二次确认。
> 定位：**管理型控制台**——数据域与同步状态、质量报告、数据字典浏览、血缘、任务与配额；**基于 REST，不直连 DB/SDK**（doc-10 §2）；本稿只定**信息架构与权限模型**，技术栈后端置。

## 1. 原则

1. **REST 单一数据面**：WebUI 只调用 doc-12 的只读接口与控制面接口；无第二条数据通道；
2. **认证与授权暂不制作**（doc-15）：首期仅本机访问（`127.0.0.1`），无登录/角色体系；多用户或远程需求出现时再启用；
3. **事件日志不保留**（个人平台首期）；**通知渠道**分离为 doc-16（飞书等，暂不制作）；
4. **只读优先**：浏览类页面全部只读；写操作集中在"任务与治理"，且二次确认；
5. **与 Agent 分工**：外部 Agent/量化消费 REST/SDK；WebUI 面向**平台治理**，不做研究分析界面。

## 2. 信息架构（导航与页面）

| # | 一级导航 | 页面与能力 | 主要数据来源 |
|---|---|---|---|
| 1 | **总览 Dashboard** | 各域健康度、SLA 违约、质量告警、任务运行、成本/配额摘要 | `/v1/freshness`、`/v1/admin/*`、质量统计 |
| 2 | **数据域 / 数据集** | 域树（cn_equity/cn_fund/…）；数据集详情页：字段与口径（字典）、PIT 类别、主键、SLA、覆盖率、质量规则、血缘、存储映射 | `/v1/datasets`、`/v1/datasets/{dataset}` |
| 3 | **同步与任务** | 任务列表/详情（job/窗口/状态/耗时/行数/错误/request_id）；重试、补数、暂停（**二次确认**）；调度日历 | `/v1/admin/jobs*` |
| 4 | **数据质量** | 规则清单、检查结果、异常明细、对账报告（引用 doc-8 报告体系）、趋势 | `/v1/admin/quality*` |
| 5 | **新鲜度 / 水位** | 每数据集 watermark、lag、覆盖率趋势、SLA 违约清单（可下钻到任务） | `/v1/freshness` |
| 6 | **血缘** | dataset 级 DAG（上游/下游、派生输出、`algorithm_id`）；点击跳数据集/算法 | `/v1/datasets/{dataset}`（lineage/derived） |
| 7 | **派生与算法** | 算法注册表（id/version/owner/inputs/docstring Formula+PIT）；**升级台账（algorithm_id / effective_from / reason）**；代次 `data_generation`；重算任务（**二次确认**） | `/v1/algorithms`、`/v1/algorithms/events`、`/v1/algorithms/generations` |
| 8 | **实体注册表（Entity Registry）** | 实体检索（entity_id / canonical / 源代码）；代码履历与外部标识；状态与属性历史时间轴（含退市） | `/v1/entities/*` |
| 9 | **快照与导出** | 研究快照列表（预留）、导出任务、下载 | `/v1/exports`、`/v1/snapshots/*` |
| 10 | **系统与治理** | API Key 管理（REST 对外）、配额与成本、版本与健康 | `/v1/admin/*` |
| 11 | **个人** | 会话、通知偏好；显示偏好 | 本地 |

## 3. 认证与授权（暂不制作）

- **个人平台定位**：首期 WebUI 仅监听 `127.0.0.1`，无账号/登录；访问控制依赖本机环境；
- **增强方案**：多用户/远程/对外开放时启用 `doc-15《认证与授权（增强功能，暂不制作）》`（本地账号 + 角色 + 会话 + OIDC 预留 + BFF）；
- **仍保留**：高风险操作二次确认（防误触，与账号体系无关）；REST 对外仍使用 API Key（doc-12，首期仅供本机脚本使用）。

## 4. 关键交互约束

1. **无直连**：所有数据经 REST；页面不缓存权威数据（Redis 缓存由 REST 层负责）；
2. **长任务异步化**：补数/导出/重算返回 job id，页面轮询或订阅状态；
3. **数字口径统一**：所有展示字段/单位/PIT 标注来自字典（doc-11），避免页面硬编码口径；
4. **危险操作幂等提示**：重复提交检测（request_id/幂等键）。

## 5. 与 REST 的接口依赖（示例）

| 页面 | REST |
|---|---|
| 数据集详情 | `GET /v1/datasets/{dataset}`、`/schema` |
| 新鲜度面板 | `GET /v1/freshness` |
| 任务详情/重试 | `GET /v1/admin/jobs/{id}`、`POST /v1/admin/jobs/{id}/retry` |
| 算法注册表 / 升级台账 / 投影代次 | `GET /v1/algorithms`、`/v1/algorithms/events`、`/v1/algorithms/generations` |
| 实体注册表 | `GET /v1/entities/{entity_id}`、`/aliases` |
